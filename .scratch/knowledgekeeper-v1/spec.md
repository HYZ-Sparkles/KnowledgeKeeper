# KnowledgeKeeper v1

Status: ready-for-agent

## Problem Statement

用户（主要是 iPad 用户，不会编程）在备考时手上有大量单选题、多选题、判断题和匹配题，散落在 PDF、Word、Excel 和网页里。做错的题没有地方沉淀，想再做一遍得重新翻文件；即使把题整理进表格，也没法按记忆规律安排复习，做错的题几天后就忘。用户需要一个打开就能用的工具，把题变成可以反复练、到期自动重现的错题本——而且题不能丢，也不能交给别人保管。

## Solution

一个部署在 GitHub Pages 上的静态网页应用，iPad 优先、可添加到主屏幕、可离线，数据只存在用户自己的浏览器里，没有账号和服务器。用户把题目从 PDF / Word / Excel 文件或粘贴的文本导入，经校对后归入分组，也可以用表单录入。在分组内练习，所有题型都用"提交"判定；做错的题按遗忘曲线（1、2、4、7、15、30 天）在到期时优先重新出现，直到完成复习。整个题库可以备份成一个 JSON 文件、随时恢复，作为浏览器存储被清理时的兜底。

## User Stories

### 导入

1. 作为用户，我希望把 PDF、Word、Excel 文件导入成题目，以便不用手打就能把文件里的题变成可练的题
2. 作为用户，我希望直接粘贴从网页复制的文本导入，以便网页上的题不用先存成文件
3. 作为用户，我希望在 iPad 上从"文件"app 里选文件导入，以便和其他 app 一样自然
4. 作为用户，我希望导入时选择新建分组或放入已有分组（默认选中"错题集"；选「＋ 新建分组…」时在对话框里起名），以便不同科目的题不混在一起
5. 作为用户，我希望导入结果先进入校对页，逐题修改、删除、合并或拆分后再写入，以便解析错误不会进题库
6. 作为用户，我希望校对页顶部显示"识别到 N 题、答案 M 个"的警示，缺失答案的题标红，以便一眼看出哪里要补
7. 作为用户，我希望题型（单选题 / 多选题 / 判断题 / 匹配题）自动推断，以便不用逐题手选
8. 作为用户，我希望在校对页改正推断错的题型和答案，以便判定正确
9. 作为用户，我希望支持"答案紧跟题目"和"答案统一在末尾"两种文本格式，以便常见卷子都能直接导入
10. 作为用户，我希望解析器容忍常见题号写法（`1.` / `1、` / `(1)` / `（1）` / `01`）、全角选项字母（`A．`）和范围写法答案（`1-5 ABCDA`），以便复制来的文本不用先整理
11. 作为用户，我希望源文件里的解析（"解析：…"）被保留，以便练习时能看到说明
12. 作为用户，我希望 Excel 按固定列（题型 | 题干 | A–F | 答案 | 解析）导入并有模板可下载，以便我能批量整理题
13. 作为用户，我希望导入 `.doc` 时得到"请在 Word 里另存为 .docx"的提示，以便我知道怎么办而不是以为坏了
14. 作为用户，我希望解析出 0 道题时看到明确提示，以便我能改用粘贴文本或手动录入

### 匹配题

15. 作为用户，我希望把"一组共用选项 + 多个子题"的题导入成一道匹配题，以便这类题也能练
16. 作为用户，我希望练习匹配题时左侧看共用选项、右侧逐个子题作答、全部选完后一次提交，以便和原来的做题方式一致、后面的子题也不被前面的答案提示
17. 作为用户，我希望提交后整道匹配题锁定，并显示每个子题的对错和正确答案，以便不会重复提交
18. 作为用户，我希望匹配题提交并显示对错后出现"下一题"，操作和其他题型一致，以便我知道这道匹配题做完了

### 录入与维护

19. 作为用户，我希望用表单手动录入一道题（选题型、填题干 / 选项 / 答案 / 解析），以便文件里没有的题也能加
20. 作为用户，我希望用表单录入匹配题（共用选项 + 多个子题），以便匹配题也能手动加
21. 作为用户，我希望在分组里点开一道题，编辑它的题干、选项、答案和解析，以便改错不用删了重加
22. 作为用户，我希望在题目页删除题目（二次确认），以便不要的题不占地方
23. 作为用户，我希望编辑题目内容不改变它已有的排期，删除题目连带删除作答记录和排期，以便数据始终一致
24. 作为用户，我希望在分组页重命名分组，以便名字贴合科目
25. 作为用户，我希望在分组页删除分组并二次确认（对话框写明连带多少道题、不能撤销），以便整理时能一次清掉
26. 作为用户，我希望首次打开就有一个默认分组"错题集"，以便不用先建组再导入

### 收藏

27. 作为用户，我希望在做题时点「收藏 / 已收藏」按钮收藏或取消收藏，以便在做题的那一刻标出重要题
28. 作为用户，我希望分组题目列表能切换"只看收藏"，以便快速找到标过的题
29. 作为用户，我希望收藏不影响排期和练习队列，以便它只是标记，不打乱复习节奏

### 练习

30. 作为用户，我希望一次只在一个分组里练习，以便专注一科
31. 作为用户，我希望所有题型都用"提交"按钮判定（包括单选题和判断题），以便不会误触就判定，操作一致
32. 作为用户，我希望多选题全对才算对，以便判定标准明确
33. 作为用户，我希望提交后立刻看到对错和正确答案，以便当场知道错在哪
34. 作为用户，我希望选项和子题保持源文件顺序，只有题目顺序随机，以便答案字母和选项对得上
35. 作为用户，我希望看到本轮进度 x / N，以便知道还剩多少
36. 作为用户，我希望一轮做完后看到本轮结果、点一下就开始重新打乱的下一轮，不记录中断位置，以便随时打开随时练
37. 作为用户，我希望每道题旁显示历史对错次数，以便知道哪些题一直错

### 遗忘曲线

38. 作为用户，我希望做错的题按 1、2、4、7、15、30 天的间隔在到期时重新出现，以便按记忆规律巩固
39. 作为用户，我希望打开分组时到期错题先出、最久到期的在前，以便最该复习的先练
40. 作为用户，我希望首页每个分组显示"到期 N 道"，以便不用逐个分组点进去找
41. 作为用户，我希望到期复习答对进入下一个间隔、任何一次答错回到第一个间隔，以便排期跟着我的表现走
42. 作为用户，我希望从未做错的题不排期，以便已经会的题不打扰我
43. 作为用户，我希望匹配题任一子题答错就算整题答错，以便匹配题和普通题的排期一致
44. 作为用户，我希望通过 30 天间隔后题目完成复习，不再排期但留在分组里，以便复习有尽头
45. 作为用户，我希望完成复习的题再答错会重新成为错题，以便不会漏掉
46. 作为用户，我希望"到期"按本地日历日算（周一答错、周二 00:00 到期），以便早上打开就能看到
47. 作为用户，我希望题目列表显示排期状态（第 k / 6 个间隔 · 何日到期或逾期几天 · 未排期 · 完成复习），以便一眼看到每题的复习进度

### 统计

48. 作为用户，我希望每次作答都被记录（含时间），以便统计有依据
49. 作为用户，我希望分组列表显示题数和总体正确率（没有作答时显示"尚未练习"），以便知道每组的掌握情况

### 备份与恢复

50. 作为用户，我希望把整个题库备份成一个 JSON 文件，以便浏览器清理存储也不会丢题
51. 作为用户，我希望用备份文件恢复题库（整库替换），以便换设备或丢数据后能找回
52. 作为用户，我希望首页显示"上次备份：N 天前"或"尚未备份"，以便不会忘记备份
53. 作为用户，我希望备份包含分组、题目、作答记录、排期状态和收藏，以便恢复后原样继续

### 平台

54. 作为用户，我希望在 iPad Safari 里把应用添加到主屏幕，全屏无地址栏使用，以便像 app 一样点开就用，且存储不被 7 天清理
55. 作为用户，我希望首次使用时在首页看到一条可关闭的"添加到主屏幕"引导，以便知道可以这样用
56. 作为用户，我希望没有网络也能打开和使用全部功能，以便地铁和教室里也能练
57. 作为用户，我希望中文界面，以便不用懂英文
58. 作为用户，我希望不用注册账号、题目不上传到任何服务器，以便零门槛、隐私有保障

## Implementation Decisions

### 架构（遵循 ADR-0003）

- 纯前端静态网页应用，无后端、无账号、无同步；部署在 GitHub Pages（子路径，用 hash 路由）；国内访问不稳时给同一份构建加 Cloudflare 备用入口，不改代码。
- 技术栈：React 18 + Vite + TypeScript + Tailwind；IndexedDB 经 Dexie；解析库 pdf.js（文字版 PDF）、mammoth（.docx）、SheetJS（.xlsx / .xls）。`.doc` 不支持。
- 工具链走国内镜像（pnpm + npmmirror）。

### 唯一外部 seam：应用核心 interface

UI 只调用一个 module——应用核心。它呈现的 interface 分五组：

- 导入：`importFromText(text)`、`importFromFile(file)` → 校对草稿（题目列表 + 警示）；`commitReview(draft, groupId)` 写入前校验草稿（题干非空、每题有合法答案、字母在选项范围内），不通过则报错、不写入。改题型、拆分、合并、改答案是 UI 对草稿的编辑，不经过应用核心。
- 分组：列表（含题数、总体正确率、到期数）、创建、重命名、删除（级联）
- 题目：录入、读取列表（含排期状态、对错次数、收藏）、编辑、删除、收藏切换
- 练习：`startRound(groupId)` → 本轮有序队列，每一项自带题目的完整内容、排期状态、对错次数、收藏，UI 不逐题再查；`submitAnswer(questionId, answer)` → 判定、正确答案、作答前的排期状态与新排期。`answer` 在单选题 / 判断题是一个字母，多选题是字母集合，匹配题是按子题序号排列的字母集合数组——整题一次提交，内部仍按子题各记一条作答，返回值里逐子题给出判定与正确答案
- 备份：`backup()` → JSON 字符串；`restore(json)` → 整库替换

应用核心 **接受** 三个依赖，不自己创建：

- **storage adapter**：生产用 IndexedDB，测试用内存实现
- **clock**：生产用系统时间，测试用固定时间
- **random**：生产用系统随机，测试用固定种子（保证轮顺序可断言）

内部 module（文本解析器、Excel 解析器、二进制文本提取、排期、轮构建、备份序列化）都是私有 implementation，不呈现给 UI，测试也不直接触碰。

### 解析规则

- 文本解析接受：题号 `1.` / `1、` / `(1)` / `（1）` / `01`（括号半角全角都算）；选项 `A.` / `A、` / `A．`；答案段既支持逐题写法（`1A 2B`）也支持范围写法（`1-5 ABCDA 6-10 BCDBA`）；判断题答案接受 `√ × 对 错 正确 错误 T F`；判断题没有选项行也能识别。
- 匹配题识别：`共用选项：` 块（A–J）后跟编号子题列表（`1. 人工智能（单选）`），子题标注单选 / 多选；答案段按子题序号对应。
- 题型推断：答案含 2 个以上字母 → 多选题；选项为"正确 / 错误 / √ / ×"或答案为判断题符号 → 判断题；有共用选项块 → 匹配题；否则单选题。校对页可改，互转范围见「界面设计」。
- 解析：题后紧跟的"解析：…"或 Excel 的解析列，提取为可选字段；没有就留空。
- 警示：末尾答案数与题数不符 → 草稿附警示并标红缺答案的题；0 题 → 返回明确错误，不生成草稿。绝不静默写入。
- Excel：固定列 `题型 | 题干 | A | B | C | D | E | F | 答案 | 解析`，首行表头，题型列可空（走推断）；不承载匹配题。提供模板文件。
- 二进制文本提取作为 adapter：`importFromFile` 先提取为纯文本，再走同一个文本解析器。提取失败给明确错误。

### 数据模型

- **分组**：id、名称、创建时间；"错题集"在首次启动时创建。
- **题目**：id、分组 id、题型、题干、选项列表（字母 + 文本，数量不设上限）、答案（字母集合）、解析（可空）、收藏标记、导入顺序；匹配题额外有共用选项列表和子题列表（每个子题：题干、单选 / 多选、答案）。判断题的选项固定为「√ 正确」「× 错误」，答案即 √ 或 ×。
- **排期**（题目级）：间隔阶段 0–6（0 = 未排期）、到期日（本地日历日）。完成复习 = 阶段标记为完成且不再排期。
- **作答**：题目 id、子题序号（非匹配题为空）、是否正确、时间。每次一行，永久保留。
- **题库元数据**：上次备份时间。
- 统计（对错次数、正确率、到期数）由作答和排期实时计算，不单独存储。

### 排期与轮

- 间隔序列固定为 1、2、4、7、15、30 天；到期日 = 作答当天的本地日期 + 间隔天数，当天 00:00 到期。
- 状态转换：从未排期的题答错 → 阶段 1；到期答对 → 下一阶段；阶段 6 答对 → 完成复习；任何一次答错（含完成复习后）→ 阶段 1；从未做错的题永远不排期。
- 匹配题：任一子题错 → 整题错；全部子题对 → 整题对。
- 判分：单选题、判断题、单选子题精确匹配一个字母；多选题、多选子题精确匹配字母集合（全对才对）。
- 轮构建：到期错题按到期日升序排在前，其余题目用注入的 random 打乱排在后；N = 到期数 + 其余数。到期题不可跳过。
- 编辑题目内容不动排期；删除题目或分组级联删除作答与排期。

### 备份

- 单个 JSON 文件，带 schema 版本号；内容包括分组、题目（含排期、收藏）、作答记录、题库元数据。
- 恢复 = 整库替换；成功后更新"上次备份时间"为备份文件中的值。
- 首页根据上次备份时间显示"上次备份：N 天前"或"尚未备份"。

### PWA 与 iPad

- manifest 支持添加到主屏幕（standalone、无地址栏）；service worker 预缓存应用壳，新版本在下次打开时生效。
- 未安装到主屏幕（display-mode 非 standalone）且未关闭时，首页显示可关闭的"添加到主屏幕"横幅；关闭状态按设备记，不进备份。
- 文件选择走系统文件选择器；备份文件经浏览器下载到"文件"app。
- iPad 优先：触摸目标、竖屏横屏都可用；桌面浏览器自然可用，不额外适配；≤760 的单列布局顺带保留，不作验收。
- 界面中文单语；代码标识符英文。品牌名显示为 Knowledge Keeper，代码标识符、包名、备份文件名为 KnowledgeKeeper。

## 界面设计

来源是选定的原型 `.scratch/knowledgekeeper-v1/design-demos/dir-1.html`（三栏文档壳）。本节只写决定：结构、状态、文案规则，以及视图与应用核心的对应；色值、字号、间距、组件形态以原型文件为唯一视觉来源，这里不抄。设计过程见同目录的 `direction-approved.md` 与 `design-demos/polish-log.md`。

### 总则

- 分工：**顶栏是动作，左栏是目录，右轨是当前视图的信息，内容栏一件事一个主动作。** 同一件事只出现一次：入口不放进右轨，状态不做入口。
- 形：暖纸底、发丝线分区，无卡片、无阴影、无大块彩色，颜色只在字和细线上。蓝只给可点的主动作，橙只给到期与强调，绿 / 红只在判定时出现。
- 触摸：按钮 42px，匹配题选项 44px，表单的「正确」与练习页的收藏按钮 40px，选项行不低于 56px；不依赖 hover。
- 字：中文系统字体栈，不装 webfont（和离线、单文件冲突，参照站也是系统字）。数字用等宽数字。
- 无障碍：文字对比度 ≥ 4.5:1，大字与图形 ≥ 3:1。图标用内联 SVG，1.2–1.5px 描边，跟随文字色。
- 反馈通道只有三种：**对话框**（需要用户决定或输入）、**持久警示条**（错误和需要处理的事，不自动消失）、**toast**（成功与轻确认，约 2 秒自动消失）。不用原生 alert / confirm / prompt：不可样式，且 iOS Safari 在 pushState 之后用返回键导航时它们会失效。
- 实现：token（色、字号、间距、3–4px 圆角）映射到 Tailwind theme；hash 路由 `#home / #group / #question / #practice / #import / #entry / #backup`。

### 壳

- 顶栏 56px、sticky：品牌 Knowledge Keeper（≤760 只留图标）；导航「题库 / 导入 / 录入 / 备份」，「题库」在首页、分组、题目、练习四个视图下高亮；右侧是日期与「今天到期 N 道」（≤760 隐藏）。
- 左栏 240px：只到分组一级——分组名 + 右侧橙色到期数（0 为灰），当前分组加粗；点分组进分组页。
- 右轨 220px：按视图给信息，不放动作。
- 内容栏：面包屑「我的题库 / …」→ 40px 标题 → 一句副标 → 药丸 → 发丝线 → 正文。
- 断点：≤1180 两栏收窄为 198 / 176px；≤960 去右轨（iPad 竖屏大多在这一档）；≤760 单列，去左栏和顶栏右侧。右轨里没有任何 iPad 竖屏看不到就不成立的东西。

### 与原型的差异

原型不再改动，实现时结构以本节为准。原型里过时或缺失、不能照抄的部分：

1. 分组页的题目行点开的是题目页，不是练习。
2. 「重命名 / 删除分组」从右轨挪到分组页工具栏；右轨「分组」块删除。
3. 左栏去掉「全部 / 到期 / 收藏」子项、「▸」和「收起分组」。
4. 练习页「这道题」的间隔、到期日、历史对错挪进内容栏的标签行；右轨只留六格刻度和一句后果说明；标签行里与提交行重复的提示语删掉；右轨「示例」块是演示物件。
5. 匹配题提交后的按钮是「下一题」，不是「回到题目列表」。
6. 新增：题目页、应用内对话框、本轮完成块、首页「添加到主屏幕」横幅、判断题与匹配题的录入表单、空状态、提取中的状态、校对页的 sticky 警示条。
7. 原型里用 toast 占位的地方（选文件、导出、恢复、收起分组）按上面的反馈通道规则替换；演示数据 `LIB` / `QBANK` 不搬。
8. 文案：对错次数统一「N 对 N 错」；过期的题显示「逾期 N 天」；首页副标改为"直到通过最后一个间隔"。

### 首页

- 副标：「N 个分组，M 道题。做错的题会按 1、2、4、7、15、30 天重新出现，直到通过最后一个间隔。」
- 药丸：「N 道今天到期」（橙）；「N 道在复习中」，即处于错题状态的题数；「上次备份 N 天前」（尚未备份或 ≥ 7 天为橙，否则中性）。
- 横幅：未安装到主屏幕且未关闭时，在副标之下显示「在 Safari 点「分享 → 添加到主屏幕」，全屏使用，存储也不会被 Safari 清理。[知道了]」。
- 分组行：组名（琥珀）+「N 题」+「正确率 N%」细条（没有作答显示「尚未练习」）+「到期 N」或「无到期」。点行进分组页。
- 右轨：「排期」说明 + 六格图例（不绑数据）；「存储」说明 + 上次备份时间（纯文字）。

### 分组页

- 副标：「N 道题，总体正确率 N%，今天到期 N 道。到期题排在最前面，最久到期的先出。」正确率 = 组内全部作答的 对 /（对 + 错）。
- 药丸：各题型数量，为 0 的不显示。
- 排期分布：一根基线、八个刻度（1 / 2 / 4 / 7 / 15 / 30 天、完成复习、未排期），高度是题数；复习中为橙，两个终态为褐。
- 工具栏：主按钮「▶ 开始练习」，旁边一句「到期 N 道先出，其余 M 道打乱」；右侧「只看收藏」开关，再右两个 ghost 文字按钮「重命名」「删除分组」。
- 题目行：题型标签、题干（琥珀）、排期文案、「N 对 N 错」，两列右对齐定宽。行上没有任何收藏控件或标记。
- 排期文案：「第 3/6 · 逾期 2 天」「第 1/6 · 今天到期」（橙）、「第 2/6 · 10 月 18 日到期」「未排期」「完成复习」。
- 列表顺序：导入顺序，新录入的排在最后。
- 空状态：列表位置「这一组还没有题。」+「导入」「录入」（跳到对应视图并预选本组）；「开始练习」禁用并提示。只看收藏为空：「这一组还没有收藏的题。」
- 右轨：「本轮」两句说明，按数据生成。

### 题目页

- 从分组页的题目行进入。面包屑「我的题库 / 组 / 题目」，标题「编辑题目」。
- 顶部一行只读状态：题型 · 排期（同列表文案）·「N 对 N 错」· 是否收藏。
- 主体是预填的录入表单（见「录入页」）；题型互转规则同校对页，匹配题不可互转。
- 底部：主按钮「保存」、ghost「取消」回列表、右侧 ghost 红字「删除题目」→ 对话框「删除这道题？它的作答记录和排期会一起删除，不能撤销。」
- 保存不动排期；成功 toast「已保存」并回列表。v1 练习页不放编辑入口。

### 练习页

- 面包屑「我的题库 / 组 / 练习」。头部：「第 n / N」+ 细进度条 +「到期题 N 道未做」（随作答递减）+ 右侧 ghost「退出练习」（不确认，回分组页）。
- 标签行：`[题型] [第 3 个间隔 · 10 月 12 日到期 · 5 对 2 错] …… [收藏 / 已收藏]`。未排期显示「从没做错过 · 6 对 0 错」，完成复习显示「完成复习 · 9 对 4 错」，逾期显示「第 3 个间隔 · 逾期 2 天 · 5 对 2 错」。收藏按钮带文字，提交后仍可切换，分组页「只看收藏」的结果随之更新。
- 题干 30px；选项是整宽行、发丝线分隔、字母 + 文本，顺序固定。判断题的选项显示「√ 正确」「× 错误」。
- 作答：单选 / 判断点一下选、再点取消；多选点选切换。「提交」在未选时禁用，旁边一句操作提示（「选一个再提交」「可多选，全对才算对」「已选 A B」）。
- 提交后：选项不可再点；正确答案的字母变绿并标「正确答案」，误选的变红并标「你的选择」；提交行隐藏，出现反馈块（内嵌纸底 + 2px 左线，绿 / 红）：「答对」或「答错」+ 一句排期后果（见下表）+「解析」段（为空不显示）+「下一题」。
- 「下一题」滚到顶部。最后一题之后是本轮完成块：「本轮完成：N 道，对 a 错 b。下一轮已重新打乱。」+ 主按钮「开始下一轮」+ ghost「回到题目列表」。
- 匹配题：标签行同其他题型；左侧共用选项面板，右侧子题列表（序号、题干、单选 / 多选标签、共用选项字母 chip）。全部子题选定后「提交」才可用，提示在「N 个子题共用一组选项，全选完再提交」与「还有 n 个子题没选」之间切换。提交后 chip：正确答案绿底绿框、误选红底删除线；反馈块写「第 2、4 个子题错了，整道题算答错」，按钮「下一题」。
- 右轨（宽屏才有）：六格刻度 +「这次答对进第 4 个间隔（7 天），答错回到第 1 个间隔」。
- 反馈文案（"作答前"是这道题提交前的排期状态；每条前先写「正确答案 X」或「你选的是 X，正确答案 Y」）：

| 作答前 | 结果 | 文案 |
| --- | --- | --- |
| 未排期 | 对 | 从没做错过，不排期，只跟着轮次出现。 |
| 未排期 | 错 | 进入第 1 个间隔，明天再出现。 |
| 复习中 | 对 | 进入第 k 个间隔，N 天后（M 月 D 日）再出现。 |
| 第 6 个间隔 | 对 | 通过最后一个间隔，完成复习，不再排期。 |
| 复习中 | 错 | 回到第 1 个间隔，明天再出现。 |
| 完成复习 | 对 | 已完成复习，不再排期。 |
| 完成复习 | 错 | 完成复习后再答错，重新成为错题，回到第 1 个间隔，明天再出现。 |

  多选题答错时补一句「漏选也算错」。

### 导入页

两步，同一个视图。

第一步：

- 工具栏：「从「文件」选择」（.pdf .docx .xlsx .xls）+「或直接粘贴文本」。选文件后按钮变「正在提取…」并禁用；完成后文本填进文本框，上方一行「已从「文件名」提取约 N 字」。
- 文本框：等宽字体、白底、可编辑。文件提取的文本也放这里——提取质量差时直接全选换成自己粘贴的，兜底路径不断。
- 文本框下方是持久警示条：0 题、格式不支持、.doc 提示「请在 Word 里另存为 .docx」、提取失败。
- 「放进哪个分组」：默认「错题集」，末项「＋ 新建分组…」→ 命名对话框，建好并选中。记住上次选择。
- 主按钮「开始校对」：点击才解析，进第二步。不显示预估题数，校对页的警示条会报数。
- 药丸：「支持 .pdf .docx .xlsx .xls」「.doc 需先另存为 .docx」。

第二步（校对）：

- 顶部警示条 sticky 在顶栏下方，右侧放这一屏唯一的主按钮「写入 N 道题」。缺答案时橙色：「识别到 N 道题，答案 M 个。第 7、9 题缺答案，标红了。」题号可点，点了滚到那一行，按钮禁用；补齐后转绿「识别到 N 道题，答案 N 个，都齐了。」，按钮解禁。
- 题干为空（含匹配题的某个子题题干）同样标红并拦住写入，文案接在同一个警示条里；某一行正在行内编辑或拆分时，写入按钮保持禁用，警示条追加「第 N 题还在编辑中，点「完成」后才能写入。」（拆分时是「先「从此处拆分」或「取消」」），避免把未完成的编辑当成已写入。写入仍被应用核心拒绝时，错误以持久警示条显示，绝不静默。
- 每行：两位序号、题型小标签 + 题干、选项行（灰）、右侧答案框（缺答案时红框、占位「缺答案」）、操作行「编辑题干」「改题型」「拆分」「与下一题合并」……「删除」。
- 答案框：统一大写、去空格；判断题接受 √ × 对 错 正确 错误 T F，写入时规范成 √ / ×；字母不在选项范围内视为缺答案；匹配题沿用源文件格式「1 AB　2 C」。
- 编辑是行内展开：点「编辑题干」或「改题型」，该行展开成录入表单（题型、题干、选项 + 「正确」、答案、解析），底部「完成 / 取消」；校验与警示条、写入按钮即时联动。
- 拆分：在题干里放光标，点「从此处拆分」，光标后的文字成为紧随其后的一题（无选项、缺答案标红）。
- 合并：「与下一题合并」——题干相接，选项拼接并重排字母，答案跟着重排保留，解析相接。
- 题型互转：只允许 单选 ↔ 多选 ↔ 判断。多选 → 单选而答案多于一个、转成或转出判断题时，答案清空标红。匹配题不能改成别的题型，别的题型也不能改成匹配题；要改就删除后录入。
- 底部「← 重新粘贴」回第一步，保留文本框内容。
- 写入成功：toast「已写入 N 道题到「组名」」，跳到该分组页。
- 右轨：「校对」说明（题型推断规则、缺答案会拦住写入）。

### 录入页

- 标题「录入一道题」，副标「文件里没有的题，用这个表单补进来。录入不改动任何已有题目的排期。」
- 第一行两个 select：题型、放进哪个分组（默认「错题集」，记住上次选择）。
- 题型决定表单：
  - 单选 / 多选：题干、选项行（字母 + 输入框 + 40px「正确」按钮；单选只能点一个，多选可点多个）、「＋ 再加一个选项」、解析。
  - 判断题：题干、「正确 / 错误」二选一、解析；没有选项行。
  - 匹配题：题干、「共用选项」列表（字母 + 文本，可增删）、「子题」列表（每个子题：题干、单选 / 多选、在共用选项里点「正确」、可增删）、解析。
- 选项行可删，字母自动重排。
- 校验，不满足时「保存到题库」禁用并提示缺什么：题干非空；选择题至少 2 个选项；单选恰好 1 个答案、多选至少 2 个；判断题有答案；匹配题至少 2 个共用选项、至少 1 个子题且每个子题有答案。
- 保存后留在表单、字段清空、toast「已保存到「组名」」，方便连续录入。
- 这份表单预填后就是题目页和校对页的编辑器。
- 右轨：「录入」说明。

### 备份页

- 副标：「题库只存在这台设备的浏览器里。浏览器清理存储、换设备、误删分组，都靠这个 JSON 文件兜底。」
- 药丸：「上次备份 N 天前」（同首页规则）、「N 道题 · M 条作答」。
- 三段，发丝线分隔：
  1. **导出备份**：主按钮「导出备份文件」→ 下载 `KnowledgeKeeper-YYYY-MM-DD.json`，同时更新「上次备份」，toast「已导出」。
  2. **从备份恢复**：「选择备份文件」→ 系统选择器 → 对话框「用「文件名」替换当前题库？文件里有 N 个分组、M 道题；当前的分组、题目和作答记录都会消失，不能撤销。」→ 确认后恢复，toast「已恢复 N 个分组、M 道题」，回首页。文件不是备份或版本不支持：本段下方持久警示条。
  3. **装到 iPad 主屏幕**：沿用原型的说明块。
- 右轨：「存储」说明 + 上次备份时间。

### 对话框

- 唯一的模态组件：标题 + 一句带数字的后果 + [取消] + [确认]；破坏性确认用红字。
- 用于：新建分组命名、重命名分组（带文本框）、删除分组（「删除「组名」及其 N 道题？不能撤销。」）、删除题目、从备份恢复。
- 不用原生 prompt / confirm；iPad 上弹出时输入法可用。

### 视图与应用核心的对应

| 视图 | 调用 |
| --- | --- |
| 首页 | 分组列表 |
| 分组页 | 分组列表（统计）、题目列表、重命名、删除分组 |
| 题目页 | 题目列表项的完整内容、编辑、删除 |
| 录入页 | 创建分组、录入 |
| 练习页 | `startRound`、`submitAnswer`、收藏切换 |
| 导入页 | `importFromText` / `importFromFile`、创建分组、`commitReview` |
| 备份页 | `backup`、`restore`、题库元数据 |

草稿的编辑（改题型、拆分、合并、改答案）发生在 UI，`commitReview` 写入前再校验一次。按设备的 UI 状态（横幅已关闭、导入 / 录入上次选的分组）不经过应用核心，不进备份。

## Testing Decisions

- **好测试的定义**：穿过应用核心 interface，断言可观察的返回值——校对草稿的内容与警示、本轮队列的顺序与长度、提交后的判定与排期、备份 JSON 的内容——不断言内部解析中间结构或数据库行。存储用内存 adapter，时钟与随机用固定值，所有测试确定性。
- **被测 module**：应用核心，经唯一 seam。重点行为：
  - 文本解析：每种题号写法、两种答案格式、范围写法答案、判断题符号、匹配题结构、解析提取、答案数不符的警示、0 题报错
  - Excel 解析：模板形状的工作簿、题型列空时走推断
  - 二进制提取 adapter：每种格式一个文字版样本（.pdf / .docx / .xlsx / .xls），只验证文本能提出来
  - 题型推断全分支
  - 排期状态机的全部转换：进入、推进、答错重置、完成、完成后再错、日历日边界（23:59 答错 → 次日 00:00 到期）、匹配题聚合
  - 轮构建：到期优先且按到期日升序、其余由固定随机决定、N 正确
  - 判分：多选集合精确匹配、漏选 / 多选都算错；匹配题整题一次提交——逐子题判定、任一子题错即整题错、按子题各记一条作答
  - 收藏切换与"只看收藏"过滤；编辑不动排期；级联删除；默认分组首启存在
  - 备份往返一致；恢复后旧数据消失；上次备份时间正确
  - `commitReview` 拒绝缺答案或字母越界的草稿且不写入；`startRound` 的队列项带排期状态、对错次数、收藏
- **Prior art**：仓库为空，无既有测试。采用 Vitest；不在 seam 上做 React 组件测试。
- **不作为测试 seam 的部分**：React 渲染、service worker、manifest、iPad 文件选择与下载——用一份简短的 iPad 手测清单覆盖（安装到主屏、断网打开、选文件、下载备份、横竖屏切换后右轨消失而状态行仍在、对话框里弹出输入法）。

## Out of Scope

- 跨分组移动题目；题目列表排序；搜索与筛选（"只看收藏"除外）；设置页；Excel 导出；打乱选项；深色模式；英文界面
- `.doc` 旧格式；扫描件、图片、公式、表格题；OCR
- 分钟级或 12 小时间隔；其他间隔算法（SM-2、Leitner）
- 单独的"复习模式"；跳过到期题
- 自动备份；云同步；账号；多设备
- 单选题 / 判断题的点选即判定
- 练习页里编辑题目；分组栏折叠；手机（≤760）的专门适配
- 原生 app、桌面安装包、代码签名
- macOS / Windows 的专门适配

## Further Notes

- 术语以 `GLOSSARY.md` 为准（题目是实体，错题是状态；匹配题不叫题组；备份还原叫恢复不叫导入；复习只指到期作答）。架构遵循 ADR-0003；ADR-0001 / 0002 已被取代。
- 两个待实现时验证的事实：iPadOS Safari 对 7 天未访问站点的存储清理策略及主屏应用豁免；pdf.js 对中文 CID 字体的文本提取质量。后者是最大技术风险，粘贴导入是兜底路径。
- HTML 原型（`.scratch/knowledgekeeper-v1/design-demos/dir-1.html`）是视觉与交互参照，没有接应用核心，不再是计划中的 UI adapter；结构与行为以「界面设计」为准，外观以原型为 token 来源，React 实现直接按「界面设计」做。
