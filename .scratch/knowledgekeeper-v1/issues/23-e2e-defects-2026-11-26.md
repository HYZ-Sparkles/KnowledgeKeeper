# 23: e2e 测试发现的缺陷

**What to build:** 用真实浏览器对 v1 全流程做 e2e 测试（录入 / 分组 / 题目 / 练习 / 导入 / 备份 / 响应式）后发现的问题。逐条修复，不改已定的行为与文案规则；修复后按同一路径回归。

**Blocked by:** None（can start immediately）

**Spec:** spec.md「界面设计 · 导入页 / 录入页 / 练习页 / 分组页」「解析规则」「测试决策」

**Status:** resolved

## 缺陷

- [x] **P1 录入保存后全局计数不刷新。** `EntryView` 的 `save()` 只写库、不刷新分组统计；保存后分组页副标/药丸/右轨仍是旧数，列表却已多一行，首页同样滞后，刷新才补上。
- [x] **P1 PDF 导入在浏览器里必然失败。** `extractFile` 调用 pdf.js `getDocument` 时没有配置 `GlobalWorkerOptions.workerSrc`，报「提取失败：文字版 PDF 无法读取（No "GlobalWorkerOptions.workerSrc" specified.）」。单测跑在 Node（fake worker），所以测试是绿的。
- [x] **P1 校对页写入按钮与校验不联动，写入失败静默。** 缺答案只统计已提交的草稿行，不含打开中的行内编辑；`commitReview` 拒绝时没有 `catch`，页面无任何反馈（例如匹配题缺题干时警示条显示「都齐了」、按钮可点、点了什么都不发生）；行内编辑未「完成」时点写入会用旧数据写入，编辑被静默丢弃。
- [x] **P2 全角括号题号 `（1）` 不被识别。** 首题被当成前言吞掉，其答案错位挂到下一题（静默写错答案）。
- [x] **P3 本轮完成后右轨「这道题」未清空。** 进入「本轮完成」块后仍显示上一题的排期说明。
- [x] **P3 空分组右轨文案。** 显示「这一组没有到期的题，0 道全部打乱。」「一轮 0 道，做完自动重新打乱…」。
- [x] **P3 文案空格。** 分组页副标「总体正确率 56%， 今天到期」（全角逗号后多一个空格）；录入/校对表单「子题 1题干不能为空」（缺空格）。
- [x] **P3 匹配题题型互转只靠 `disabled`。** `QuestionForm.changeType` 没有守卫，程序化选择可把匹配题转成单选题（正常鼠标/键盘不可达）。
